Contradictions found while filling the cells

The Sensor checks the wrong Detekt version

sdlc_project_doctor expects Detekt 1.x settings (build: maxIssues: 0 and plugin id io.gitlab.arturbosch.detekt). guidelines-android.md prescribes Detekt 2.x's warningsAsErrors: true, which it says replaces maxIssues. A project that follows the guideline would fail the doctor.

sdlc_project_doctor.md:44–48 vs guidelines-android.md (Detekt)

The Hooks check tests the wrong security tool

The doctor requires the security-guidance plugin, but every command runs the built-in /security-review. So the check confirms something the workflow never calls.

sdlc_doctor.md:57 vs implement_change / verify_story / vibe_a_story

A Boundary written in prose is overridden by prose

guidelines-git.md says "CRITICAL: never ever commit directly", but sdlc_exp_four_in_one and sdlc_exp_vibe_a_story run git commit themselves. With no permission rule, the most recent instruction the agent read decides.

guidelines-git.md:4 vs sdlc_exp_four_in_one.md:82, sdlc_exp_vibe_a_story.md:223

The Sensor for the prompts is never wired in

check_guardrails.sh is free and runs in under a second, but nothing runs it automatically: this repo has no CI and no pre-commit hook. The one check aimed at the harness itself relies on someone remembering to run it.
